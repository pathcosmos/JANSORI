# 본학습 비용 조합과 실증 계획

상태: **계획·기존 증거 재계산 완료, 외부 전송·복원 실증 전**. 현재 F8 리허설은 유지하며 F9의 저장·복구 계획을 미리 준비한다. 이 문서는 본학습 승인이나 보존정책 적용 완료를 뜻하지 않는다.

## 비용 기준과 우선순위

사용자가 이번 대화에서 **현재 서버는 별도 비용이 없다**고 확인했다. 현재 서버의 추가 청구 비용은 0원으로 계산한다. GPU·CPU 작업시간 단축은 완료시간 개선이며, 서버 대여료 절감액으로 계산하지 않는다. 외부 저장소는 독립 백업을 확보하기 위한 추가 지출이다. 외부 서비스의 저장·다운로드·API·세금·환율만 별도 계산한다. 현재 서버의 다른 유료 상품으로 이전하는 것은 이번 비교에 넣지 않는다.

현재 서버만 쓰면 추가 지출은 0원이지만, 서버 전체 유실에 대비한 외부 복구 사본은 없다. **2026-11-07 사용자 최신 지시: 업로드·다운로드 비용 무료/최소화 → 저장 용량 비용 → 속도** 순서로 선택한다. 무결성·실제 재개·안전한 보존은 모든 후보의 공통 필수 조건이다.

1. 업로드/다운로드 트래픽 요금과 전송에 수반되는 PUT/GET/목록·multipart 요청료, 데이터 조회료, 중계서비스 요금까지 합산해 무료 또는 최소인 경로를 먼저 선정한다. 무료 전송량 초과 및 계정 전체 요청 사용량도 확인한다.
2. 같은 전송 비용 조건에서 저장량·보관기간·최소 용량/최소 기간·작성중 사본을 포함한 저장 요금을 비교한다.
3. 앞의 비용 조건이 같거나 차이가 불분명한 후보끼리 전송·검증·복원 속도를 비교한다. 더 빠르다는 이유만으로 전송비가 더 드는 상품을 우선하지 않는다.

이 순서는 비용을 하나로 합쳐 속도와 교환하는 방식보다 우선한다. 저렴하지만 느린 후보도 백업 적체를 안전하게 처리하고 필요한 복구를 수행할 수 있다면 채택할 수 있다. 서버 내부에서 추가 비용 없이 수행하는 CPU/GPU 최적화는 계속한다. 기존의 속도 최우선 문구는 외부 저장·전송 선택에 적용하지 않는다.

당초624.33GiB 주 대상은 추가 후보5.607GiB와 함께 사용자 승인 후 삭제 완료했다. 합계1,394파일/673.859GB를 지웠고 NFS 여유 증가629.931GiB를 실측했다([삭제·복구 기록](DATA_RETENTION_AND_RECOVERY.md)). 현재 무료 서버에서 이 공간을 비워도 직접 절감되는 요금은 0원이다. 공간 부족 회피 효과와 외부 보관 비용을 구분한다. 해당 파일의 실제 전송 크기 합계는 약667.73GB이며, 할당 크기를 외부 저장 청구량으로 쓰지 않는다.

위 달러 값은 **지정 용량을 한 달 내내 유지하고 다운로드 초과가 없는 경우**, 무료량·반올림·추가 사본·API·세금을 제외한 용량 기반 근사값이다. 실제 비용은 서비스별 집계 규칙으로 다시 산정한다. R2는 일별 peak의 월평균을 쓰므로 새 사본 업로드와 오래된 사본 삭제가 겹치는 시간의 용량도 중요하다. 10일만 사용했다면 해당 사용기간을 반영하며 B2의 무료 다운로드 기준도 월평균 저장량이다. 마지막 체크포인트의 이후 보관기간을 0일로 임의 가정하지 않는다.

공식 확인:

- [B2 요금](https://www.backblaze.com/cloud-storage/pricing): $6.95/TB·월부터, 월평균 저장량3배까지 무료 다운로드, 초과$0.01/GB. [API 표](https://www.backblaze.com/cloud-storage/transaction-pricing)의 일반 A/B/C 요청은 무료이며 event notification은 별도다. API 표의 오래된 저장 단가 문구와 상충하므로 저장 단가는 현재 가격 페이지를 기준으로 하되 실제 계정 견적을 확인한다.
- [R2 요금](https://developers.cloudflare.com/r2/pricing/): Standard $0.015/GB·월, 인터넷 egress·데이터 조회료0, A $4.50/백만·B $0.36/백만 요청. 무료량·청구 단위 반올림 적용. 단기 체크포인트에 Infrequent Access를 적용하지 않는다.
- [Storage Box 상품](https://www.hetzner.com/storage/storage-box/): 1/5TB 등 정액 용량, 트래픽 무제한. 이번 공식 페이지의 텍스트 응답에는 동적 가격 숫자가 없어 **€3.20/€10.90는 이전 조사값**이며 발주 전 국가/VAT/통화별 재확인이 필요하다. [구조](https://docs.hetzner.com/storage/storage-box/general/)는 단일 호스트 RAID이며 독립된 여러 호스트 사본과 같지 않다.
- [Wasabi 요금](https://wasabi.com/pricing): $7.99/TB·월부터, 1TB 최소·90일 최소 과금 때문에 이번 짧은 rolling checkpoint의 1차 실증 후보에서 제외한다.

1TB Storage Box는 약784GB의 제한된 묶음에는 들어가지만, 여기에 최종 token payload244.80GB만 더해도 약1.029TB다. 최종 원문·split DB·증거까지 모두 보관하려면 별도 전체 inventory와 상위 용량이 필요하다. 제한된 cold 백업을 전체 프로젝트 재해 복구라고 부르지 않는다.

## 비용·전송 계산

전체 추가비용 = 외부 저장료 + 외부 다운로드 초과료 + API/별도 서비스 비용 + 세금·환율 영향. 현재 서버 추가요금은 사용자 확인에 따라0이다. 총시간에는 저장·해시·전송·복원·재실행·경합을 포함하며, 겹쳐 수행한 시간을 중복 합산하지 않는다.

동일한 청구 GB 기준으로 월평균 저장량을 S, 월 다운로드량을 D라 두면, 무료량·API·반올림 전 근사는 다음과 같다.

- B2: `0.00695 × S + 0.01 × max(0, D - 3 × S)` 달러.
- R2 Standard: `0.015 × S` 달러 + API.
- 두 비용은 대략 **D = 3.805 × S**에서 같아진다. 실제 서비스 집계·무료량·수신 검증 방식이 다르므로 최종 선택 기준 자체는 실측 청구 예상값이다.
- S=116GB이면 약441GB 다운로드부터 R2가 유리해지는 근사다. 모든228개 checkpoint를 전수 GET하면8,816GB로, B2 약$85.49 대 R2 약$1.74(+API)의 예시가 된다. 이는116GB를 한 달 유지하는 가정이며 실제 사용기록 기반 견적이 아니다.
- 원격 저장 빈도250/500/1000step은 총 전송량 약8.816/4.408/2.204TB다. 원격 간격을 늘리면 서버 전체 유실 시 잃는 학습량도 늘어난다. 로컬 저장 간격·평가 간격과 별도로 결정한다.

38.667GB를63.10분마다 보내려면 순수 payload 기준 평균 약81.7Mbps가 필요하다. 업로드·검증 완료를30분 이내로 잡으면 최소 약171.9Mbps에 프로토콜·재시도 여유가 추가된다. 다음은 회선 보장이 아닌 이론적 하한이다.

| 유효 payload 속도 | checkpoint 1개 단방향 전송 |
|---|---|
| 100Mbps | 약51.6분 |
| 200Mbps | 약25.8분 |
| 500Mbps | 약10.3분 |
| 1Gbps | 약5.2분 |

서버 전체 유실 시에는 checkpoint만 받는 시간이 아니다. 최종 token payload와 checkpoint만 합쳐도283.47GB이고, tokenizer·설정·코드·증거·환경 및 후속 native 평가가 요구하는 원문/split의 복구도 고려해야 한다. 이 데이터의 보관 위치와 재확보 절차가 없으면 checkpoint 전용 백업은 완전한 재해 복구가 아니다.

## 실증 순서와 판정

### 1. 현재 가능한 준비

이번 완료 범위는 기존 실측/파일 크기 대조, 하드웨어 실측, 요금 확인, 비용 시나리오와 실증 계약 작성이다. 원격 계정 생성·업로드·삭제·새 GPU 실험은 수행하지 않는다. 결과는 `runs/training_cost_review_v1/analysis.json`에 기록한다. 진행 중 producer와 실행 설정은 유지한다.

다음 구현은 별도 run 디렉터리의 백업 도구로 한다. 작은 복사본에서 업로드 중단, 손상, 누락된 rank 파일, 잘못된 part 순서, 잘못된 입력/설정, commit marker 조기 발행을 거부하는지 검증한다. 과거 REF-TRAIN 재개 성공을 새 원격 복원 성공으로 승격하지 않는다.

### 2. 외부 전송 실증

목적지·리전·시험 prefix·대상 manifest·한도를 정한 뒤 해당 업로드를 확인받는다. 첫 후보는 **R2 Standard와 Storage Box**다. 전송 비용 조건을 먼저 확인하고, 그다음 동일 보존 범위의 실제 저장비, 마지막으로 속도를 비교한다. B2는 다운로드·재시도·검증까지 무료 한도에 들어가는 구체 사용량을 입증한 경우 추가한다. 재생성 가능한 원본/중간본667.73GB를 유료 원격 보관하는 것을 기본 전제로 삼지 않는다. 해당 원본/중간본 및 추가 후보는 별도 사용자 승인에 따라 삭제 완료했다. 이후 다른 자료 삭제는 기존 확인 규칙을 유지한다.

- 실제 닫힌 DCP shard 약4.83GB와 실제 compressed Parquet 표본으로 시작한다. 먼저 worker2/4, multipart64/256MiB를 한 축씩 비교하고, 포화되지 않을 때만8worker를 추가한다. 전 조합을 무조건 반복하지 않는다.
- 압축하지 않은 전송을 기준으로 한다. zstd 저레벨 후보는 출력 일치를 필수로 확인하고 대표 표본의 전송 비용, 저장 비용, 압축+전송+복원+검증 총시간 순으로 판단한다. 체크포인트 간 증분·중복제거 이득을 미리 가정하지 않는다.
- 선정 설정으로19파일 전체 checkpoint를 새 prefix에 올리고 별도 로컬 경로로 내려받아 **전수 SHA256·크기·파일 목록**을 대조한다. backend당2회만 먼저 측정하며, 차이가 불분명한 경우 예산 내에서만 추가한다. 2회로 p95나 장기 가용성을 주장하지 않는다.
- 중간 업로드 종료/재개, 실패 후 재시도, 새 checkpoint 업로드와 이전 사본 공존을 시험한다. 기존 유일 사본을 실험 대상으로 삭제하지 않는다. 시험 원격 데이터 정리도 승인된 prefix 범위로 한정한다.
- 첫 라운드 전체 상한 제안: **업로드200GB, 다운로드200GB, 저장200GB, 48시간, 외부 청구$10**. 복구용 여유와 기존 계정 사용량·청구 규칙을 반영한다. backend2개×full38.667GB×2회=154.67GB/방향이므로 표본·재시도에 남은 예산만 쓴다. 상한 도달 시 산출물을 보존하고 중단한다. 이는 실행 승인이 아니다.

### 3. 실제 학습 재개와 경합 검증

F8 전체 리허설·최종 native 평가·대기 중 monitored3B 검증이 끝나 GPU 사용이 가능한 때에 수행한다. 복원된 DCP를 새 시험 경로에서 읽어 동일한8GPU·tokenizer/mix/seed/batch·RNG 계약으로 bounded 재개를 실행한다. 연속 실행과 model/optimizer/RNG·실제 샘플/step을 대조한다. 현재 loader가 허용하지 않는 경로/계약을 맞추려고 metadata를 고쳐 통과시키지 않는다. 필요한 경우 별도 복원 harness를 구현하고 검증한다.

GPU 시험 추가 예산은 우선 총1시간 이내 제안이다. 실제 checkpoint2→4 재개 경로를 재사용하고, 본학습을 실증 수단으로 시작하지 않는다. 이후 같은 부하의 짧은 학습+백업 동시 구간으로 총시간·tok/s 저하를 비교한다. 후보 목표는 upload+검증≤30분, checkpoint hot restore+검증+load≤30분, 처리량 저하≤2%, backlog 증가 없음이다. 이 수치는 **참고용 속도 관측값**이며 사용자 SLA나 비용 우선 후보의 자동 탈락 조건이 아니다. 안전하게 관리할 수 없는 적체·복구 불능은 필수 운영 조건으로 구분하고, 단순히30분보다 느리다는 이유로 유료 전송안을 선택하지 않는다. cold 재해 복구시간은 더 큰 입력 묶음으로 별도 산정한다.

사전 예산 후보: CPU 최대8개, OMP2/Arrow2, transfer worker2→4→8, RSS32GiB, 추가 로컬192GiB, 영구 보고서1GiB, GPU0(전송 단계). host128GiB·NFS/로컬 각각200GiB reserve 및 현재 job들의 향후 peak를 먼저 차감한다. 직전 hardware_profile/resource_admission과 명시적 thread/TMPDIR 설정을 적용하고 sampled RSS 외 종료 peak도 기록한다. 30초 로컬 watcher에 등록하며 모델을 매 poll 호출하지 않는다. 경합 시 보조 작업부터 줄인다.

### 4. 선택 후 새 본학습에 적용

수신 검증과 실제 재개를 통과한 backend에 한해 새 본학습 계약에 연결한다. 기본 후보는 최신3개 **완전 재개 상태** + 로컬 작성중1개이며, retry backlog는 별도 여유로 산정한다. full 상태에는 모델·optimizer·전 rank RNG·meta·source ledger·입력/코드 계약·내용증명을 포함한다.

- B2 native의 [part 검증](https://www.backblaze.com/apidocs/b2-upload-part)과 [ordered part 완료](https://www.backblaze.com/apidocs/b2-finish-large-file)를 실제 선택 클라이언트에서 확인한다. SHA 메타데이터나 multipart ETag만으로 서버 수신 SHA256 증명이라고 부르지 않는다.
- R2는 [S3 호환 표](https://developers.cloudflare.com/r2/api/s3/api/)에 따라 선택한 API·checksum 종류를 실제 검증한다. 증명이 부족하면 full GET/SHA를 비용·시간에 포함한다.
- Storage Box는 [SSH의 sha256sum](https://docs.hetzner.com/storage/storage-box/access/access-ssh-rsync-borg/)으로 수신 파일을 검증하는 경로를 실증할 수 있다. 제한된 shell에 임의 script·pipe가 가능하다고 가정하지 않는다.
- immutable run/step prefix에 payload를 올리고 내용에 묶인 manifest/commit을 마지막에 발행한다. 최초 전체 복원 및 정기 복원훈련과 매 업로드 수신 검증의 역할을 구별한다.
- **현재 native `keep_ckpts` 정리는 원격 ACK 전에 삭제한다.** 현재 코드는0을 허용하지 않으므로0으로 끄지 않는다. 본학습 코드 변경 없이 사용할 경우 max_steps보다 큰 값으로 자동 정리를 사실상 비활성화하는 방식을 먼저 검증하고, 승인된 별도 관리기가 ACK·검증 후 허용된 새 실행 사본만 정리한다. 아직 해당 관리기는 구현·실증되지 않았다.
- 업로드 실패·backlog·reserve 접근 시 새 생성/학습을 안전하게 멈추고 최신 검증 사본을 보존한다. 최신3개 유지 숫자를 맞추려고 미검증 파일을 지우지 않는다. 원격 구버전·delete marker·unfinished multipart 등 청구에 남는 데이터도 실제 정책으로 관리한다.
- 평가용 model-only는 검증된 export/loader가 준비된 후 주요 시점에만 추가한다. full resume의 대체가 아니며, bf16 변환 전 가중치 크기·압축률을 비용 확정값으로 쓰지 않는다.

본학습 시작·기존 자료 삭제/덮어쓰기·외부 업로드의 확인 규칙은 [CLAUDE.md](../CLAUDE.md)를 따른다. 구체적인 시험 manifest·목적지·예산이 준비된 시점에 실행 확인을 받고, 보존정책과 본학습은 최종 F9 검토에서 별도로 확정한다.

현재 개발 보조 권장: F8 및 독립 실증 준비 GPT-6 Astra / High. F9 최종 설정·예산·복구 판단 GPT-6 Astra / xhigh. 현재 앱 선택값을 확인하거나 자동 변경한 것은 아니다.

## 추가 절감 대안 재확인 (2026-11-07 사용자 질의)

공식 요금 재조회 및 Hetzner 상품 HTML의 접근성 가격 문자열을 다시 확인했다. Storage Box는 **1TB €3.20/월, 5TB €10.90/월, VAT 별도**가 반환됐다. 위 표의 이전 견적은 이번 조회에서 재확인된 값이다. 결제 국가·통화·세금에 따른 실제 주문 금액은 별도다. 트래픽은 무제한이나 S3 API를 제공하는 다중 호스트 Object Storage와 구조가 다르며, 백업/복원에는 SFTP·rsync·Borg와 수신 SHA 검증 경로를 검토할 수 있다.

- **약116GB 최신3개만 외부 보관**: R2 Standard 저장료는 무료량 제외 약$1.74/월, 계정의 월10GB 무료량을 전부 쓸 수 있으면 약$1.59/월이다. 요청료·일별 peak·동시 작성 사본·세금은 별도다. 외부로 모든 checkpoint를 보내더라도 최근3개만 남으면 보관량과 누적 전송량은 다르다.
- **약784GB 제한 묶음 보관**: Storage Box 1TB 정액과 비교한다. 1TB를 넘는 전체 프로젝트 백업에는 상위 용량/별도 inventory가 필요하다. 최신3개와 재생성 가능한 cold 후보를 모두 보관해야 한다고 가정하지 않는다.
- **기존 독립 PC/NAS/HDD와 정액 회선이 있으면**: SFTP/rsync/Borg/restic으로 받는 방법도 가능하다. 기존 장비·충분한 여유 공간·무종량 회선 조건이면 외부 저장/API 종량료0이며 전기·디스크 고장/교체·운영 비용은 남는다. 장비 보유/회선 조건은 미확인이다. 새 장비 구매는 초기비용까지 비교하고, 학습 서버 내부 scratch만으로는 서버 유실 대비 독립 사본이 되지 않는다.
- **외부 보관량 자체 축소**: 재확보 가능한 raw/중간본은 revision/SHA/정제 코드·복구 묶음을 보존하는 선택을 비교한다. 복구 시 원격 가용성과 재정제 시간은 남는다. full resume는 최신2~3개, 주요 시점은 검증된 model-only export로 구분하는 안이며 export·loader 검증 전에는 용량 절감 완료로 계산하지 않는다. 승인 없는 보존 수 축소/자료 삭제는 하지 않는다.
- **IDrive e2 추가 확인**: [공식 가격](https://www.idrive.com/s3-storage-e2/pricing)은 일반 PAYG 최소1TB/$6·월이며 무료 다운로드는 active storage 3배 정책이다. 첫해 할인과 일반/특정 고객별 가격이 섞여 있어 장기 무제한 무료 전송 대안으로 보지 않는다. B2도 월평균 저장량3배 무료 조건이 있으므로 검증·재시도·복원 총량을 먼저 계산한다.

현재 추천은 **독립 장비가 이미 있으면 비용 조건 확인 → 소량 필수 checkpoint는 R2 Standard → 수백GB 이상을 자주 복원하면 Storage Box** 순서다. 서버 전체 유실을 감수하면 현재 무료 서버만 사용하는 추가지출0원 선택도 있지만, 동일한 외부 복구 기능을 제공하지 않는다. 네이버 실제 상품/리전/청구량이 확인되지 않아 정확한 절감률은 산출하지 않았다. 이번 조사는 새 외부 업로드·구독·삭제를 실행하지 않았고 기존 실행 작업은 변경하지 않았다.
