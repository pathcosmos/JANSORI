## 목적과 범위

사용자 확정 범위: **데이터 자체를 제외한 프로젝트 대부분의 소스**, 모델·학습·평가 코드, 최적화 탐색 기법과 도구, 중간중간 측정한 벤치마크 성능까지 포함한다. 데이터 탐색·선정, 다운로드, 중간 정제, 중복 검사·제거, 최종 품질 감사·입력 확정, 분할·토크나이저·토큰화, 검증·자원 운영·보존·복구 도구와 테스트를 함께 공개한다.

최소 예제만 공개하는 방식이 아니라 실제 사용 경로와 실험 방법을 보존하고, 처음 쓰는 사람을 위한 작은 실행 경로를 별도로 제공한다. 실패하거나 채택하지 않은 최적화도 결과를 선별해 이유·검증 범위와 함께 제공한다.

사용자가 **public 배포**와 이후 **진행**을 명시해, 별도 public 저장소 생성·검증된 소스 발행까지 실행했다. 같은 공개 여부를 다시 묻지 않았다. 새 본학습·데이터 삭제/덮어쓰기·전체 데이터 재생성은 이 작업에 포함하지 않았다. 아래 계획표는 실행 전 정한 완료 조건과 판단 근거로 보존한다.

## 저장소 구성 제안

기존 비공개 저장소는 유지하고 별도 공개 저장소를 새 이력으로 만드는 안을 권장한다. 전체 구현 범위에 맞춘 가칭은 `korean-dense-llm`이다. 이름 사용 가능 여부는 아직 조회하지 않았다.

첫 공개 버전은 `v0.1.0`을 제안한다. 의미는 코드·재현 예제·현재까지의 실험 기록을 공개한다는 것이며, 진행 중인 본학습이나 최종 모델 품질 검증 완료를 뜻하지 않는다. 본학습 완료를 첫 소스 공개의 선행 조건으로 두지 않는다. 추후 최종 결과는 후속 버전에서 반영한다.

초기에는 common/data/tokenizer/scripts/tests 등 기존 import 구조를 유지해 불필요한 재작성과 동작 변경을 줄인다. README는 한국어·영어 진입점을 두고, docs에는 단계별 사용법·설계·품질 한계·검증 범위·성능 측정 조건을 둔다. examples에는 작은 CPU 실행과 실제 대규모 설정 예제를 둔다. 소스 이력 manifest에는 원본 경로·원본 SHA·공개 경로·공개 SHA·수정 이유를 남긴다.

model/train/eval도 기존 구조를 유지한다. `experiments/`에는 실험별 recipe·설정·선별한 기계 판독 결과·해석을 묶고, 원래 실행 코드 위치를 연결한다. 원본 실험 파일을 일괄 복사하지 않으며 개인 경로·원문 표본·생성 본문·checkpoint 포함 여부를 파일별로 검토한다.

## 최적화·벤치마크 공개 형식

실험마다 목적 → 비교 후보 → 고정 조건 → 명령 → 결과 → 채택/기각 이유 → 한계를 기록한다. 속도가 빠르더라도 출력 동일성·수치 조건에 실패한 후보를 권장 설정으로 제시하지 않는다.

- 데이터 처리: worker/thread/batch, SHA 병렬화, SQLite cache/RSS, 로컬/NFS, split·BPE·토큰화·발행의 총시간·처리량·peak 메모리·출력 동일성·재개.
- 학습: eager/compile, micro batch, GPU 수·모델 규모·sequence length, bf16/FP32·cast·수치 비교, 처리량·VRAM·저장·복원 비용.
- 결과 필수 항목: 코드/설정 식별자, 입력 규모·식별자(본문 제외), 하드웨어와 컨테이너 제한, 패키지 버전, warmup/compile 시간 포함 여부, cache 상태, 반복 횟수, elapsed/처리량/메모리 측정법, 실패·중단·미검증 상태.
- 반복 측정이 없으면 단회 결과로 표시하고 통계적 우위를 주장하지 않는다. 작은 실험의 최적값을 전체 규모 최적값으로 바꾸어 설명하지 않는다.
- GPU 처리 성능 벤치, 수치 정확성 검증, native loss/생성 평가, 공식 언어능력 벤치마크를 구분한다. 미실행 공식 평가·최종 학습 결과는 미완료로 남긴다.
- 기존 완료 실험 증거를 우선 재사용한다. 공개 준비를 위해 큰 GPU 실험이나 본학습을 반복하지 않으며, 재실행이 필요한 경우 이유·예산·진행 중 학습과의 충돌을 먼저 검토한다.

## 단계별 실제 작업 목록

### P1 — 최신 소스와 실험 근거 고정

1. 작업 트리의 추적/미추적 Python·shell·설정·문서·tests 및 runs 내부 재사용 코드를 조사한다. 캐시·checkpoint·데이터 payload의 전체 해시는 이 조사에 필요하지 않다.
2. `source_inventory.json`에 경로·크기·SHA256·역할·의존성·공개/제외/보류·사유를 기록한다. 기존 237개는 출발 목록이며 해당 개수로 공개 범위를 제한하지 않는다.
3. `experiment_inventory.json`에 각 benchmark/probe의 코드·설정·실제 결과 파일·실행 시각·검증 상태를 연결한다. 현재 파일과 과거 실행 당시 코드가 다르면 차이를 표시하거나 보존된 실행 코드를 함께 연결한다.
4. 완료된 결과만 시점 고정해 복사하고, 진행 중 결과는 마지막 완료 구간을 명시한다. 복사 전후 stat/hash가 달라지면 그 파일만 다시 확인한다.
5. 외부 코드 인용·라이선스 고지·환경 의존·절대경로·자동 실행의 위험한 기본값을 목록화한다. 기존 운영 코드 수정 없이 공개본에서 해결할 항목을 정한다.

사용자 보고: 포함/제외/보류 파일 수, 실험 목록, 수정 필요한 항목, 후속 작업량. 판단이 필요한 출처·동작 예외가 있을 때만 해당 선택지를 보고한다.

### P2 — 독립된 공개 패키지와 문서 구성

1. 원본과 분리한 새 staging 경로에 허용 목록으로 복사한다. 원본 Git index·branch·실행 중 학습 코드·입력을 수정하지 않는다.
2. common/data/tokenizer/model/train/eval/scripts/tests의 기본 import 구조를 유지한다. 오래된 실험도 의미가 있으면 experimental로 분류해 남긴다.
3. 하드코딩된 서버 경로·실행 ID를 인자로 바꾸는 등 공개에 필요한 수정만 하고 `public_changes.json`에 원본/공개 SHA와 수정 이유를 남긴다. 수정한 구현은 과거 벤치에서 직접 측정된 코드와 구별한다.
4. CPU quickstart와 실제 대규모 실행 recipe를 분리한다. dependencies도 data/CPU 검증과 GPU 학습의 요구 사항을 구분하고 실제 시험한 버전을 기록한다.
5. README 한국어/영어, 단계별 사용법, 데이터 확보 안내, 모델·학습 설계, 재개·보존 절차, 알려진 한계, 기존 라이선스 고지를 정리한다. 데이터 자체는 고정 버전 외부 링크로 연결한다.
6. 합성 입력 생성기를 제공해 데이터 파일을 동봉하지 않고 작은 end-to-end 실행을 가능하게 한다. 실제 tokenizer는 다운로드 경로·SHA를 안내하고 quickstart용 작은 tokenizer는 합성 입력에서 생성한다.

사용자 보고: 공개 트리, 주요 실행 명령, 원본 대비 변경 요약, 아직 실행하지 못하는 경로.

### P3 — 작은 독립 재현과 실험 보고서 검증

1. staging만 보이는 별도 실행 디렉터리·환경에서 import/CLI와 해당 CPU 회귀 검사를 수행한다. 원본 저장소의 PYTHONPATH·미공개 runs 파일을 은밀하게 참조하지 못하게 한다.
2. 합성 입력으로 정제→중복→감사/최종 확정→그룹 분할→작은 tokenizer→토큰화→mix→tiny 학습/평가/저장/재개를 검증한다. 작은 모델 경로와 실제 3B/FSDP 전용 경로의 차이를 문서화한다.
3. 네트워크 다운로드 재개는 관련 fixture 검사와 예산을 제한한 실제 입력 검사를 구분한다. 업스트림 원본 전체 재다운로드를 기본 검사로 삼지 않는다.
4. 중단 재개, 변경된 입력 거부, 손상된 완료 증명 거부, 그룹 중복, 토큰 내용 동일성 등 관련 기존 검사를 재사용한다. 공개 패키징으로 생긴 위험에만 검사를 보완한다.
5. 실험별 보고서의 숫자를 원본 기계 판독 결과와 대조한다. 표·그림에는 입력 크기·환경·단회/반복·compile/warmup 포함 여부를 붙인다. 합성/소량 결과를 전체 처리량으로 승격하지 않는다.
6. 작은 CPU 검증을 CI에 연결하는 설정을 준비한다. GPU 검사는 실행 명령·요구 환경·기존 실제 결과를 제공하되 이번에 다시 실행하지 않았다면 명시한다. 유료 runner는 도입하지 않는다.

사용자 보고: 통과/실패/건너뜀 검사와 이유, CPU 재현 로그, 실험 요약 표, 미검증 GPU 경로. 필수 CPU 경로가 실패하면 P4 발행 준비 완료로 표시하지 않는다.

### P4 — 발행할 정확한 내용 확정

1. 최종 파일 목록·크기·SHA256·원본 대비 diff를 고정하고 데이터 payload·인증정보·사적 로그·절대경로의 포함 여부를 검사한다.
2. 프로젝트 자체 코드와 제3자 코드·문서·데이터 고지의 범위를 확인한다. 기존 공개 recipe의 라이선스는 적용 범위가 확인된 파일에 재사용한다.
3. README의 각 실행 명령을 검증 로그에 연결하고, 완료·실험적·미구현·진행 중 상태를 명확히 표시한다.
4. 저장소 이름 사용 가능 여부와 생성 경로를 확인한다. 앱이 생성 기능을 제공하지 않으면 가능한 GitHub CLI/API 인증을 읽기 전용으로 확인한 후 대체 경로를 정한다. 기존 저장소 push 권한과 새 저장소 생성 가능 여부를 혼동하지 않는다.
5. public 저장소 주소, 첫 버전, 공개 파일 목록, 검증 결과, 알려진 한계와 발행 방식을 사용자에게 보고한다. public 방침은 이미 확정되어 동일 확인을 반복하지 않는다.

### P5 — public 발행과 외부 사용자 관점 확인

1. 확정된 저장소에 검토한 snapshot만 새 이력으로 발행한다. 기존 private 저장소 전체 이력을 자동 공개하지 않는다.
2. 첫 commit과 `v0.1.0` tag, 릴리스 설명, 기존 데이터 배포본 링크를 연결한다. 태그 대상 commit과 manifest를 기록한다.
3. 인증 없는 별도 경로에서 public clone을 수행해 파일/해시·작은 CPU quickstart를 확인한다. 외부 CI 결과와 로컬 성공을 구분한다.
4. 코드·태그·문서·검증이 서로 일치할 때 발행 완료를 보고한다. 수정이 필요하면 새 commit/patch 버전으로 기록하고 기존 발행 증거를 보존한다.

## 진행 원칙과 보고

- 단계 시작/변경 때 권장 개발 모델·effort를 알리며 자동 전환이나 자동 위임은 하지 않는다. 현재 계획 P0는 Sol/Medium, 실제 P1~P4 준비·검증은 Sol/High가 기본이다.
- 첫 작업은 P1이며 P1 결과로 후속 작업량을 산정한다. 고정된 시간 약속 대신 각 단계 완료 조건과 남은 항목을 보고한다.
- 현재 학습의 GPU·메모리·I/O 예산을 먼저 확보한다. 공개 준비는 작은 코드·선별 결과 복사와 CPU 검사 중심이며, 자원집약 검사 전 실측으로 worker/thread/RSS/임시 경로를 지정한다.
- 다음 단계의 의존성·예제·문서 준비는 현재 단계 검사가 진행되는 동안 여유 자원 안에서 수행할 수 있다. 필수 검증을 통과하기 전 발행하지 않는다.
- 데이터 본문 공개, 진행 중 본학습 변경, 새 대규모 GPU 실험이 필요해지면 현재 소스 공개 범위와 구분해 근거·영향·선택지를 보고한다.
- 최종 전달물은 public 저장소 URL, 고정 tag/commit, 공개 파일 manifest, 재현 명령, 실험 목록/성능표, 검증 보고서, 알려진 한계다.

## 검증 원칙과 실행 경계

- REF-DATA/REF-TOK 및 WORKFLOW 실제 완료 조건을 적용한다. 과거 운영 증명은 재사용 가능한 근거지만 새 공개본의 실행 통과를 대신하지 않는다.
- 작은 합성 fixture의 순차 전체 실행을 먼저 검증하고, 고정 revision의 제한된 실제 입력 검증은 읽기량·통신량을 정해 수행한다. 원본 일부가 정리된 상태이므로 전체 재생성 완료라고 표현하지 않는다.
- 이전 코드와 공개 코드의 정책·출력 동일성을 확인한다. 예제용 편의 변경은 실제 대규모 실행 계약과 구분한다.
- CPU fixture CI를 기본으로 하고 GPU/대규모 검증은 선택 실행으로 문서화한다. 새 테스트는 공개 패키징의 의존성·재개·내용 불변 위험에 집중한다.
- 장시간 검사 전 hardware_profile로 재측정하고 현재 학습의 최대 자원·안전 공간을 우선 확보한다. GPU 본학습과 데이터 producer의 코드·설정·입력은 변경하지 않는다.
- 비용 순서는 전송비 최소화 → 저장비 → 속도다. 이번 소스 계획에 데이터 중복 업로드·유료 서비스 도입은 포함하지 않는다.
- 새 GitHub 저장소 생성 경로와 발행 권한은 P4 이전에 확인한다. 이번 연결 확인은 실제 push 성공 증명이 아니다.
- 사용자 진행 지시와 public 방침에 따라 검토 가능한 공개본·대상 경로를 먼저 완성한 뒤 발행했다. public 여부를 다시 묻지 않았으며 자동 서브에이전트 위임은 하지 않았다.

## 다음 작업

이번 요청의 첫 public 소스 배포는 완료됐다. 후속 버전에서는 본학습 최종 결과나 새 최적화 측정을 실제 완료한 후 추가할 수 있으며, 이번 대화 종료 후 자동 원격 갱신을 예약한 것은 아니다. 일반 상태 조회 권장 GPT-6 Luna / Low, 새 공개본 수정/검증은 GPT-6.1 Sol / High.
