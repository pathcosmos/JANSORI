2026-11-07 사용자 선택: **무료만, 6개 소스를 모두 준비한 뒤 공개, 여러 저장소로 분산, 본문 호스팅이 어려워도 재작업에 필요한 자료 공유**. 이 문서는 공개 준비 계약이다. 업로드 요청은 받았지만 원격 공개 완료와 구별한다.

추가 확정: 사용자는 **모두 public 공개**를 지정했다. 데이터 6개와 안내·재현 저장소 모두 `private=false`로 생성하며 비공개 staging/비공개 저장 용량 확보는 사용하지 않는다. 공개 업로드 자체에 대한 재승인은 요청하지 않는다. 무료 공개 용량, 쓰기 인증, 본문별 귀속·고지 조건은 별도로 확인한다. 아래 비공개 100GB 설명은 비교 근거일 뿐 현재 실행 제약이나 확보 과제가 아니다.

## 저장소 구성

계정은 `pathcosmos`, 상위 안내 저장소는 `ko-en-code-math-corpus`로 정한다. HF의 `smollm-corpus`처럼 corpus는 자료 묶음을 설명하며, 소스별 이름은 언어·원본·처리를 직접 표시한다. 공식 강제 명명 규칙이라는 뜻은 아니다. 이름에 특정 tokenizer의 토큰 수나 검증하지 않은 품질·권리 보장을 넣지 않는다.

| 소스 | 예정 dataset 저장소 이름 | 현재 정제본 GB(10진) | 문서 수 |
|---|---|---:|---:|
| 한국어 위키 | korean-wikipedia-cleaned | 0.530 | 455,397 |
| FineWeb2 한국어 | korean-fineweb2-cleaned | 99.934 | 58,664,414 |
| HPLT2 한국어 | korean-hplt2-cleaned | 62.424 | 27,434,232 |
| FineWeb-Edu 영어 | english-fineweb-edu-cleaned | 67.329 | 34,704,836 |
| OpenWebMath | open-web-math-cleaned | 13.950 | 5,448,920 |
| GitHub 코드 | github-code-filtered | 3.584 | 2,148,459 |

크기는 출처 정보·공개용 재패킹 이전 값이다. 각 소스에 별도 카드·조건·원본 manifest를 두고 안내 저장소에서 고정 commit들을 연결한다. 같은 본문을 안내 저장소에 중복 업로드하지 않는다. 임의 크기로 여러 계정을 만들거나 계정 제한을 회피하는 분할은 계획하지 않는다.

## 무료 용량과 게시 방식

[HF 저장 정책](https://huggingface.co/docs/hub/storage-limits)은 공개 무료 저장을 best-effort로 정의하고, 저장소가 아닌 **계정 전체** 용량을 계산한다. 따라서 위 분산은 필요한 자료만 받기·조건 관리·부분 재개를 위한 구성이지 무료 총량 확보의 증거가 아니다. 무료 계정 비공개 100GB는 전체 비공개 staging에 부족하다. 현재 계정의 공개 허용량/잔여량은 확인되지 않았다. 업로드가 시작된다는 사실만으로 전체 용량·무상 장기 보존을 보장하지 않는다.

1. **작은 재현 묶음:** 6개 소스 카드·고정 revision·원격 파일/SHA·정제/분리/토크나이저 코드와 설정·통계·알려진 한계를 함께 공개 준비한다. 본문 전체를 못 올려도 독립적으로 사용할 수 있게 한다. URL 목록만으로 기존 split까지 복구가 완료됐다고 표시하지 않는다.
2. **본문 묶음:** 무료 용량과 소스별 재배포 조건이 확인된 공개판을 각 저장소에 넣는다. 기존 원문은 보존하고 별도 export 경로에서 준비한다. 용량 확보 실패 시 유료 전환이나 작은 일부를 전체 완성본으로 표시하지 않는다.
3. **전체 버전 발행:** 6개가 모두 준비된 후 업로드한다. 다중 저장소 간 원자적 동시 commit은 보장할 수 없다. 각 저장소의 검증된 commit을 모은 안내 저장소의 `release.json`을 마지막에 발행해 전체 버전 완성을 표시한다. 중간 저장소에는 staging/미완료를 표시한다. 이것은 일부 데이터의 일시적 가시성을 막는 장치가 아니다. 한 순간의 완전 동시 비공개→공개가 필수라면 별도의 충분한 staging 용량이 필요하다.
4. `preupload_lfs_files` 뒤 저장소별 단일 commit 방식을 작은 공개 가능 fixture로 먼저 확인한다. 이 방식도 외부 전송이고 권리·용량 확인을 대신하지 않는다. [설치 SDK 0.34.4 업로드 문서](https://huggingface.co/docs/huggingface_hub/v0.34.4/guides/upload)를 기준으로 재개/실패/commit 후 확인을 구현한다. 대용량 uploader의 무한 재시도는 권한/용량 오류에서 중지하도록 제한한다.

최신 실제 인증 확인(서버 UTC2026-11-07T15:43): `pathcosmos`, token role=`write`. `.bashrc` 적용 interactive shell과 일반 비대화형 프로세스 모두 확인했다. 안내 저장소를 실제 public 생성하고 README905bytes 업로드 및 인증 없는 다운로드/bytes·SHA 일치 검증 완료. commit `dfc37737ee60d12fdf3e026aa2c72513795ad809`, 근거 `runs/dataset_release_plan_v1/auth_check_v1/report.json`. 과거 read-only 인증 장애는 해소됐다. 대용량 본문과 재현 묶음 전체는 아직 업로드되지 않았다. 토큰은 대화·산출물에 저장하지 않는다. 결제·PRO·유료 bucket·유료 전송 중계는 사용하지 않는다. 무료 지원 여부 문의는 초안만 작성하며 별도 지시 없이 전송하지 않는다.

## 재작업 패키지의 내용과 완료 기준

- 726개 최종 파일의 출처 repo/revision/원본 shard/URL/SHA, 최종 파일 행수·크기·기존 SHA와 원본 선택 정책을 포함한다. 영어 sample/100BT 앞56개, 코드 spread64개를 고정한다. 과거 pilot1개는 최종726개 목록에서 제외한다.
- 정제·PII 마스킹·필터·소스 순서·정확중복 처리, 코드의 원래 UTF8/들여쓰기 보존 규칙과 실행 당시 복구 코드 snapshot을 보존한다. 최신 코드 snapshot과 역사적 실행 코드를 혼동하지 않는다.
- canonical split의 contract ID·seed·그룹 정책·train127,565,418/eval1,290,840·기존 DB SHA를 함께 기록한다. 실제 split DB 또는 전체 문서별 assignment export는 아직 공개 묶음에 없다. 새 환경에서 재생성하고 논리 assignment 동등성을 검증하거나 경량 sidecar를 추가해야 **정확한 split 복구**가 완료된다.
- 최종 tokenizer 파일·해시, mix·토큰화 설정·검증 요약을 포함한다. 로컬 절대 경로를 그대로 실행하지 않도록 복구 안내를 둔다. 토큰 바이너리 전체는 첫 공개의 필수 호스팅 대상이 아니다.
- 라이선스는 DB/packaging/개별 본문/자체 코드를 구별한다. 웹 묶음의 ODC-By·HPLT CC0를 모든 원문의 허락으로 표시하지 않는다. 위키 귀속·CC BY-SA 버전 불일치, 코드 원 Git commit·LICENSE/NOTICE 누락을 명시한다. 자체 코드의 공개 라이선스는 아직 지정되지 않아 오픈소스 재사용 허락 완료로 표시하지 않는다.
- 공개용 파일은 명시적 allowlist로 구성한다. 토큰·인증·개인 연락처·운영 로그·체크포인트를 통째로 포함하지 않는다. 카드/재현 코드/manifest도 비밀정보 검사와 제3자 고지 검토 후 업로드한다. 공개 제작자명 기본값은 계정명 `pathcosmos`; 연락 경로는 HF Community 제안이며 비공개 삭제 요청 연락처는 미정이다.

`runs/dataset_release_plan_v1/distributed_v3/packages/`는 **로컬 초안**이다. 하위 7개 폴더의 카드와 CHECKSUMS는 전체 본문 또는 전체 재생성 검증 완료를 뜻하지 않는다. 전송용 `upload_staging/`에서는 재현 자료를 하나의 압축 파일로 묶어 작은 파일을 수백 개 commit하지 않게 한다. 원본 다운로드·6소스 정제의 기존 4096행 표본 검증은 재사용하되 전수 복구 성공으로 확대하지 않는다. 위키 provenance pilot도 128행 연결 성공에 한정한다.

## 본문 공개판의 남은 검증

1. 각 행을 고정 원본 shard/row와 연결하고 필요한 URL·귀속·고지·수정 설명을 복원한다. 위키 128행 pilot 성공을 전체 1.29억 행 coverage로 쓰지 않는다. 매칭 충돌/누락은 별도 보고한다.
2. 소스별 공개 근거와 남은 예외를 확정한다. 공개 제외가 필요하면 사유/행수와 원래 코퍼스 대비 차이를 기록한다. 53만 코드 repo의 라이선스 라벨을 원 commit/개별 파일 권리 확인으로 간주하지 않는다.
3. PII/secret 점검, 소스·언어·길이별 표본 검토 및 오류 기록. 기존 regex 마스킹만으로 개인정보가 없다고 보장하지 않는다.
4. canonical train/eval을 보존한 Parquet export. 1~4GiB 후보를 대표 입력에서 비교하고 실제 압축 크기·읽기 성능·출처 오버헤드로 선택한다. 단일 commit당 파일 권장 수를 맞추되 불필요한 재패킹은 피한다.
5. 모든 outgoing 파일 SHA256/크기/행수, 중단 재개 시 변경 입력 거부, fresh consumer 로드 및 split coverage 검증. 샘플 로드가 전수 무결성을 대신하지 않는다.
6. 저장소별 원격 commit 고정·파일 목록/내용 검증. 원격 SHA가 의미하는 대상을 확인하고 Xet 내부 ID를 파일 SHA로 가정하지 않는다. 강한 동일성 증명이 없으면 다운로드 SHA로 검증한다. 실패한 전송은 원본을 지우지 않고 로컬 journal로 재개한다.

## 자원과 실행 순서

F8 및 평가 producer를 유지한다. 새 대규모 작업 전에 hardware_profile·resource_admission과 checkpoint/평가 예약량을 갱신한다. 단순 free 공간을 전부 사용하지 않는다. 기존 조회의 NFS 약1TiB/local 약1.9TiB free는 미래 checkpoint·임시공간 예약 전 수치다. 전체 raw 약394GB와 새 공개본을 즉시 중복 적재하는 실행은 아직 배정하지 않았다.

현재는 작은 코드/metadata 복사와 검증만 수행한다. 원본 복원은 source/shard window로 진행하고, 대표 입력에서 worker/cache/I/O를 측정해 전체 실행 설정을 확정한다. 영구 NFS 원문과 로컬 scratch를 구별하고 추가 삭제는 수행하지 않는다. 무료 다운로드 전송과 저장 용량을 확인한 후 확장한다. 전체 법적 검토·네트워크 처리 시간은 아직 측정되지 않아 완료 시각을 약속하지 않는다.

다음 순서: 로컬 7개 초안/검증 → 쓰기 인증·자체 코드 공개 조건 → 6소스 재현 묶음 공개 → 무료 본문 용량·귀속 보완 → 본문 export/검증 → 소스별 전송 → 전체 버전 인덱스 발행. 재현 묶음 공개와 전체 텍스트 공개는 별도 상태로 보고한다.
