## 측정 범위

같은 물리 H200 GPU 0을 한 형식씩 단독 사용했다. 3개 형식 × 98개 품질 요청, 별도 함수 프롬프트 3 × 12개, KoBEST 1,404개 × 3형식, 3 × 65개 단독 성능 요청을 수행했다. KoBEST와 함수 추가 시험은 단독 성능 시험 후 진행했다. 2GPU 추가 시험은 조합당 5종 입력에 순차·병행 각 1쌍이다. 양자화가 같더라도 서버·커널·KV 캐시 설정이 바뀌면 속도나 생성 결과가 달라질 수 있다.

사실 질문 예시에서 세 형식은 대기 중 가장 많은 기체에 이산화탄소, 가장 큰 바다에 대서양이라고 답했다. 자체 문항의 정답 표기는 첫 답만 비교한다. 수학에서 동치 식을 적고 최종 정수를 쓰지 않은 출력도 오답이다. 색상 독해는 같은 설계의 인공 문맥이며 방해 문장 반복 여부가 길이 차이를 만든다. 자체 문항은 독립으로 작성했으며 학습 데이터 오염 여부를 전수 대조하지 않았다.

코드에는 호출 전에 AST를 분석하고 첫 함수 본문만 보존했다. 빈 본문 대신 docstring만 있는 함수는 Python 구문 분석에 성공해도 실행 본문이나 단위 사례 점수를 얻지 못한다. 코드를 수정하거나 들여쓰기를 보충하지 않았다. 허용 AST와 내장 함수만 사용하고, 별도 작업 디렉터리·빈 환경·CPU/RAM 제한·파일 및 네트워크 시스템 호출을 차단하는 자식 프로세스에서 채점했다. 추가 프롬프트는 실행 결과를 바탕으로 확인한 탐색적 대조로, 모델에 두 예시와 반환문 접두어를 모두 제공했다. 48개 사례는 고정된 시험용 입력·기대값이다.

KoBEST 선택지는 문장 뒤에서 각 한 토큰이므로 전체 로그확률과 토큰당 평균의 순위가 같다. 같은 문항을 2,000회 paired bootstrap한 정확도·차이 구간을 보고했다. 이 구간에는 prompt 선정이나 학습 오염의 불확실성이 포함되지 않는다. [KoBEST 원본 자료와 라이선스](https://huggingface.co/datasets/skt/kobest_v1/tree/a5ea15e3ac77ed694b79f6204eb31889a2ba989f)

이어쓰기 표본의 단일 AI 블라인드 평가는 24개 응답을 입력·출력별로 합친 15개 텍스트에 수행했다. 0점은 새 서술 없음, 1점은 시작은 연결되지만 반복 지배, 2점은 서로 다른 세부 내용으로 전개다. 세 형식 모두 98개 기본 품질 요청에서 생성 상한 전에 멈춘 응답은 0개였다. [블라인드 판정 및 이유](story-blind.json) · [형식 연결표](story-key.json) · [문서별 paired PPL 구간](ppl-bootstrap.json)

## 모든 단독 조건

5회씩 교차 측정했다. 지연과 TTFT는 성공한 개별 요청 중앙값이다. TTFT는 첫 비어 있지 않은 텍스트 청크를 클라이언트가 읽은 시각 기준이다. gRPC·서버 내부의 첫 디코딩 시각과 다를 수 있다. 동시 요청일 때 큐 대기와 전송을 포함한다. 그룹 출력 처리량은 요청 묶음의 wall time 기준이다. 최대 VRAM·PSS는 각 0.5초 표본과 요청 그룹 직전·직후 값을 포함한 관측 최고치다. 5개 반복으로 불안정한 p95는 산출하지 않았다. 이 시험은 로컬에 저장된 배포 커밋을 재사용했으므로 신규 다운로드 시간은 재측정하지 않았다. 최초 다운로드·무결성과 기존 로딩 시간은 [배포 검증 기록](../3b_47k_hub_release_v1/jansori-hub-v1/RELEASE_REPORT.md)에 있다. 이번 표는 예열 후 요청만 대상으로 한다. 캐시된 모델 파일에서의 기동·모델 적재 및 초기 요청은 서버 로그와 형식별 calibration에 별도 보관했다. Q4 calibration 최종 파일은 재개 후 추가 준비 요청의 값이다. 기존 4,096토큰 전체 forward 검증은 [BF16 승인 근거](../3b_47k_hub_release_v1/bf16-accepted-v1/result.json)에 있다.

### H200 두 장에서 요청을 병행한 경우

GPU 0에 BF16, GPU 1에 Ollama 한 형식을 적재한 뒤 1,024토큰 입력과 32토큰 출력을 두 서버에 각각 요청했다. 형식 조합별로 서로 다른 입력 5개를 사용했다. 같은 입력을 순차와 병행에 모두 사용하고 어느 쪽을 먼저 측정할지는 교대했다. 각 측정 전 별도 1,024토큰 요청으로 직전 입력 캐시가 그대로 재사용되는 경우를 줄였다. 서버 시작·모델 로딩은 이 표에서 제외했다.

| 동시 상주 형식 | 순차 / 병행 묶음 지연 중앙값 (초) | 병행 요청 중첩 중앙값 (초) | 두 출력 모두 동일한 입력 | 동일 출력 쌍만의 순차 / 병행 중앙값 (초) | 최고 동시 합산 VRAM, 순차 / 병행 (MiB) |
|---|---:|---:|---:|---:|---:|
| BF16 + Q8_0 | 0.568 / 0.323 | 0.240 | 4/5 | 0.551 / 0.324 | 13889.8 / 13889.8 |
| BF16 + Q4_K_M | 0.556 / 0.324 | 0.235 | 3/5 | 0.559 / 0.324 | 12595.8 / 12595.8 |

양쪽 모델이 상주한 상태이므로 순차 요청도 두 모델의 VRAM을 유지한다. 동일 출력 쌍 수가 적을 때는 속도 차이를 동일 품질에서 보장되는 개선으로 해석하기 어렵다. 기존 공개 검증의 서버 시작부터 종료까지 잰 수치는 다른 지표다.


2GPU 첫 시도에서 순차와 병행의 생성 텍스트가 달라 중단됐다. 동일 입력·설정으로 전체 시험을 다시 수행하고 출력 일치 여부와 요청 중첩을 함께 기록했다. 첫 시도의 완료 전 데이터는 최종 표에서 제외했다. [최종 2GPU 원시 결과](dual.jsonl) · [최초 시도](dual-attempt1/dual.jsonl)
